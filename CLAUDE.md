# voidaform.ru — сайт дизайн-бюро Void & Form

## Что это
Статический сайт (чистые HTML/CSS/JS, без сборки и зависимостей) авторского
дизайн-бюро Void & Form: дизайн интерьеров и ремонт квартир. Язык — русский.
Референс концепции: bureauslovo.com (минимализм, пастельные тона).
Телефон компании: +7 (967) 771-11-20 (в коде — tel:+79677711120, wa.me/79677711120,
 t.me/+79677711120). Почта: info@voidaform.ru — ящик создаётся в панели Beget
 (раздел Почта) с пересылкой на личный адрес.

## Структура проекта
- `index.html` — главная: hero (сплит текст/фото), манифест, проекты, философия,
  услуги, процесс, FAQ, контакты.
- `projects/*.html` — 3 страницы проектов. **Не редактировать руками** — генерируются
  скриптом `scripts/build_projects.py` (данные проектов внутри скрипта, запуск из корня).
- `css/style.css` — вся стилистика; дизайн-токены в `:root` (палитра, шрифт, сетка).
- `js/main.js` — меню, reveal-анимации, лайтбокс, форма (отправка ведёт в WhatsApp).
- `assets/img/*.jpg` — фото интерьеров; `assets/logo-*.svg` — логотип;
  `favicon.svg`, `privacy.html`, `sitemap.xml`, `robots.txt`.

## Дизайн-система (редизайн 07.2026)
- Стиль: архитектурный минимализм, монохром. Белый `#FFF` → светло-серый `#F5F5F5`,
  тёмные секции `#141414`, акцент `#3A5254` (взят из hero-фото). Никаких скруглений.
- **Один шрифт на весь сайт — Montserrat** (как у референсов anredesign.com и
  kerimovarchitects.com). Заголовки weight 300, лейблы — uppercase 11px с трекингом .2em.
- **Шрифт хостится локально** (`assets/fonts/montserrat-{latin,cyrillic}.woff2`,
  вариативный, 62 КБ) — Google Fonts не подключается: надёжнее и быстрее в РФ.
  Подключение — через `@font-face` в начале `css/style.css` + preload в `<head>`.
- **Логотип** — `assets/logo-mark.svg` (знак) и `logo-full.svg` (с плашкой и текстом),
  оба продублированы inline в HTML (в шапке — знак + текст, в футере — полная версия).
  Геометрия восстановлена по присланному скрину: квадрат сверху + полуокружность снизу
  с общим центром и радиусом R; плашка проходит через центр (полуширина 1.44R).
- `--edge` в `:root` — отступ, которым full-bleed hero выравнивается по колонке
  контейнера. Без него логотип шапки и заголовок hero разъезжаются на экранах >1480px.
- **`.hero__media img` спозиционирован `absolute`** — обязательно. Фото вертикальное
  (1400×2095), и при обычном потоке оно растягивало hero до 1468px при экране 950:
  текст центрировался в этой высоте, сверху зияла пустота. С absolute hero всегда
  ровно 100svh, а снимок обрезается через `object-fit: cover`.
- У всех `<img>` проставлены `width`/`height` (реальные размеры файлов) — CLS = 0.
  В страницах проектов их подставляет `build_projects.py` через PIL, руками не писать.

## Грабли / важное
- **Проекты (grafit, akvarel, glubina) — реальные работы заказчика** из PDF-альбомов
  в Google Drive, папка «Примеры работ» (id 1fqC5GFI4UaOJb3P2bmhFcwvewpYZsHgO):
  1.pdf = 47,6 м² (grafit), 2.pdf = 4-комн. (akvarel), 3.pdf = 159,6 м² (glubina),
  все — ЖК RedSide, Москва, 2019. Изображения извлечены из PDF (PyMuPDF, встроенные
  картинки страниц, без рамок чертежей), ужаты до 1600px/q82.
- `assets/img/hero.jpg` — реальное фото заказчика (Drive, «Главная картинка»),
  апскейл 720×1080 → 2160×3232 (Higgsfield bytedance), хранится 1400×2095.
  Вертикальное — поэтому hero сделан сплитом, а не полноэкранным фоном.
- **Пути на страницах относительные** (не абсолютные!) — сайт должен работать и на
  GitHub Pages в подпапке /voidaform.ru/, и на корне домена.
- Цены на сайте не указываются (как у конкурента bureauslovo.com) — «уточняется по телефону».
- SEO уже разложено: JSON-LD (ProfessionalService, FAQPage, BreadcrumbList), OG-теги,
  canonical на https://voidaform.ru. При смене домена — менять и в
  `scripts/build_projects.py` (константа SITE), и в index/sitemap/robots.
- **Заявки уходят в Telegram** через `api/lead.php` (PHP на Beget есть — там
  жил старый WordPress). Токен бота и id чата лежат в `api/config.php`,
  который **не хранится в репозитории**: его собирает GitHub Actions из
  секретов `TG_BOT_TOKEN` / `TG_CHAT_ID`. Бот — `@voidaform_bot`.
  Если обработчик недоступен или не настроен, `js/main.js` открывает WhatsApp
  с текстом заявки — запасной путь, заявка не теряется.
  Адрес обработчика у каждой формы свой (`data-endpoint`), потому что пути
  относительные: `api/lead.php`, `../api/lead.php`, `/api/lead.php` на 404.
  Защита: скрытое поле-ловушка `.form__trap`, проверка телефона на 6 цифр,
  лимит 5 заявок с IP за 10 минут (файл во временной папке).
  Форм две — в секции контактов (`#lead-form`) и в модалке (`#callback-form`),
  обе обслуживает `wireLeadForm()` в `js/main.js`. У обеих есть скрытое поле
  `source` — оно уходит в текст заявки строкой «Откуда: …».
- **Все призывы к действию открывают модалку, а не уводят на другую страницу.**
  Разметка — `<a class="btn" href="…#contacts" data-modal-open="Надпись">`:
  ссылка остаётся в HTML как запасной путь без JS и как внутренняя ссылка для
  поисковиков, а `js/main.js` перехватывает клик через `preventDefault()`.
  Значение `data-modal-open` становится заголовком окна и источником заявки.
  Кнопки-`<button>` для этого не использовать — потеряется fallback.
- `.nav a.btn` — отдельное правило: иначе `.nav a` (специфичность выше `.btn`)
  перебивает кнопке в мобильном меню размер шрифта, отступы и цвет.
- **Модалка на телефоне не ставит фокус в поле** (`matchMedia("(hover: hover) and
  (pointer: fine)")`): иначе сразу выезжает клавиатура и закрывает окно. Фокус
  уходит на `.modal__box` (`tabindex="-1"`), ловушка Tab это учитывает.
  Поля ввода на `max-width: 640px` — ровно 16px: при меньшем размере iOS зумит
  страницу при тапе в поле. Окно поджато до ~410px по высоте, чтобы влезать
  вместе с клавиатурой; в ландшафте (`max-height: 560px` + ширина ≥640px)
  поля перестраиваются в две колонки.
- Блоки `.reveal` без JS остались бы невидимыми (`opacity: 0`), поэтому в `<head>`
  каждой страницы есть `<noscript>` со стилем, возвращающим их видимость.
  В `build_projects.py` фигурные скобки внутри этого стиля экранируются (`{{ }}`).
- Плавающая кнопка связи (`.fab`) — правый нижний угол, только `max-width: 999px`.
  Показывается сразу при загрузке страницы (по требованию заказчика), появление —
  CSS-анимацией `fabIn` с задержкой .4s, без участия JS и без привязки к скроллу.
  Прячется при открытом меню и модалке через `body.is-locked` (там нужен
  `animation: none`, иначе анимация с `forwards` перебивает скрытие).
- **Три режима шапки** (замеряно, не на глаз): полная версия требует ≥1251px,
  иначе телефон с иконками уезжает за край. До 999px — бургер-меню,
  1000–1250px — в шапке только кнопка «Оставить заявку», от 1251px — всё.
- Цифры в блоке «Философия» (9 лет / 64 проекта / 8 400 м²) — заглушки, не подтверждены.

## Команды
- `python3 scripts/build_projects.py` — перегенерировать страницы проектов.
- Локальный просмотр: `python3 -m http.server 8765` из корня.
- Адаптивный аудит (5 страниц × 23 разрешения; сервер должен быть поднят):
  `NODE_PATH=/opt/node22/lib/node_modules node scripts/audit_responsive.js`
  Ожидаемый результат — «✓ проблем не найдено».

## Деплой
- Хостинг — **Beget** (аккаунт `dudareid`, сервер `ssl.dream.beget.com`),
  там же DNS и почта домена. Папка сайта: `dudareid.beget.tech/public_html/` (домен привязан к техдомену).
- Выкладка автоматическая: push в `main` → GitHub Actions
  (`.github/workflows/deploy.yml`) заливает файлы по FTP.
  Доступы в секретах репозитория: `FTP_SERVER`=dudareid.beget.tech,
  `FTP_USERNAME`=dudareid_deploy (привязан к папке сайта), `FTP_DIR`=`/`,
  `FTP_PASSWORD`. Подробности и разбор ошибок — в `DEPLOY.md`.
- На хостинг едут только файлы сайта; `scripts/`, `.github/`, `CLAUDE.md`
  и `DEPLOY.md` исключены в секции `exclude` воркфлоу.
- `.htaccess` — https и без www, 301 со старых адресов WordPress
  (`/about/`, `/service/`, `/contacts/`, `/wp-*`), кэш и gzip.
- Старый WordPress **уже убран** (04.08.2026): шаг «Убрать старый WordPress»
  в workflow перенёс его файлы в `public_html/_old_wp/` через lftp. Папка
  закрыта в `.htaccess` правилом `RewriteRule ^_old_wp(/|$) - [F,L]` → 403,
  все `/wp-*` адреса отдают 301 на главную. Шаг идемпотентен, удалять его
  из workflow не нужно. Когда архив станет не нужен — папку можно снести
  вручную в файловом менеджере.
- `/wp-admin/` и `/wp-login.php` без cookie `beget=begetok` отдают 200 —
  это антибот-заглушка Beget на уровне nginx, а не WordPress. С cookie
  (как у реального браузера) отдают 301 на главную. Проверять эти адреса
  нужно с `curl -b "beget=begetok"`, иначе результат вводит в заблуждение.
