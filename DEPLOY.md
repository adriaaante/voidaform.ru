# Публикация сайта на хостинг

Хостинг — **Beget**, аккаунт `dudareid`, домен `voidaform.ru`.
Сайт статический: никакой базы данных и PHP не нужно, просто файлы.

После настройки (пункты 1–3, делаются один раз) обновление сайта =
**один `git push`**. Больше ничего запускать не нужно.

## 1. Старый сайт (выполнено)

Сейчас в `public_html/` лежит старый сайт на WordPress. Его нужно оттуда
убрать, иначе его файлы останутся рядом с новыми.

Удалять не обязательно — можно сохранить «на всякий случай». Главное:

> ⚠️ **Складывать нужно вне `public_html/`.** Всё, что лежит внутри этой
> папки, доступно из интернета. Если убрать старый сайт в подпапку вроде
> `public_html/old/`, он останется открыт по адресу `voidaform.ru/old/`:
> поисковики проиндексируют его как дубль сайта, а необновляемый
> WordPress — это ещё и типовая дыра, через которую взламывают хостинг.

**Как сделать в панели Beget → Файловый менеджер:**

1. Открыть папку `voidaform.ru/` (на уровень выше `public_html`).
2. Создать здесь папку `_old_site` — она уже вне зоны доступа из интернета,
   рядом со служебными папками вроде `logs`.
3. Зайти в `public_html/`, выделить всё содержимое и перенести в `_old_site/`.

Ещё компактнее — выделить всё в `public_html/`, нажать «Архивировать»,
получившийся `.zip` переместить в `voidaform.ru/` (или скачать себе),
а `public_html/` очистить. Архив занимает меньше места и точно ничего
не выполнит.

Дополнительно: у Beget есть собственные резервные копии
(панель → **Бэкапы**), они хранятся автоматически несколько дней —
так что подстраховка есть и без ручного архива.

## 2. Разово: создать FTP-доступ

Панель Beget → **FTP** → создать аккаунт (или использовать основной).
Понадобятся три значения:

| Что | Где взять | Пример |
|---|---|---|
| Сервер | раздел FTP в панели | `ftp.beget.com` |
| Логин | имя FTP-аккаунта | `dudareid` или `dudareid_site` |
| Пароль | задаётся при создании | — |

## 3. Разово: добавить доступы в GitHub

Репозиторий на GitHub → **Settings** → **Secrets and variables** →
**Actions** → кнопка **New repository secret**. Создать четыре секрета:

| Имя секрета | Значение |
|---|---|
| `FTP_SERVER` | `dudareid.beget.tech` |
| `FTP_USERNAME` | `dudareid_deploy` |
| `FTP_PASSWORD` | пароль, выданный при создании аккаунта |
| `FTP_DIR` | `/` |

Секреты хранятся в зашифрованном виде и не видны в логах.

> `FTP_DIR` равен `/`, потому что FTP-аккаунт `dudareid_deploy` создан
> с привязкой к `/dudareid.beget.tech/public_html/` — при подключении он
> сразу попадает в папку сайта и выше неё не поднимается.
> Домен voidaform.ru указывает на папку технического домена, отдельной
> папки `voidaform.ru/` на аккаунте нет.

## Как обновлять сайт дальше

```bash
git push
```

Всё. Через 20–40 секунд изменения на сайте.

Посмотреть, как прошла выкладка: GitHub → вкладка **Actions**.
Зелёная галочка — сайт обновлён, красный крест — открыть и прочитать ошибку.

Выложить вручную, без изменений в коде: **Actions** → *Deploy to Beget* →
кнопка **Run workflow**.

---

## Что именно попадает на хостинг

Выкладываются только файлы сайта. Служебное — исходники скриптов,
заметки, настройки GitHub — остаётся в репозитории и на хостинг не едет:

```
index.html  404.html  privacy.html  robots.txt  sitemap.xml
favicon.svg  .htaccess
css/  js/  assets/  projects/
```

Перед заливкой проверяется, что все ключевые файлы на месте — если
чего-то не хватает, выкладка останавливается и сайт не ломается.

## Если что-то пошло не так

**Сайт не обновился, в Actions ошибка авторизации** — проверить секреты
`FTP_SERVER` / `FTP_USERNAME` / `FTP_PASSWORD`.

**Файлы залились не туда** (сайт не открывается, но в панели файлы есть) —
поправить `FTP_DIR`.

**Нужно откатить сайт на прошлую версию** — в GitHub найти нужный коммит,
`git revert <хеш>` и `git push`. Actions выложит предыдущее состояние.

**Не работают стили или шрифты после переезда** — проверить, что залился
файл `.htaccess` (он начинается с точки, некоторые FTP-клиенты скрывают
такие файлы).
